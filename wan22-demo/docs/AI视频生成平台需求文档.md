## 1. 产品概述

### 1.1 产品定位

一款面向创作者和企业的专业级 AI 视频生成平台，基于 ComfyUI 工作流引擎和 Wan 2.2 14B MoE 混合专家架构模型，提供电影级品质的文生视频、图生视频和首尾帧过渡视频创作能力。

### 1.2 产品愿景

让每个人都能用自然语言或一张图片，快速生成电影级品质的动态视频，降低视频创作的门槛，释放创意生产力。

### 1.3 核心价值主张

| 价值维度     | 描述                               |
| -------- | -------------------------------- |
| **创作门槛** | 从专业技能 → 自然语言 / 一张图片即可创作          |
| **生成品质** | Wan 2.2 14B MoE 双专家架构，电影级美学与运动表现 |
| **生成效率** | 从传统制作数天 → 分钟级生成                  |
| **灵活可控** | 提示词、参数、工作流三重控制维度                 |
| **商业可用** | Apache 2.0 协议，支持商业场景部署           |

### 1.4 模型架构说明

Wan 2.2 14B 采用 **MoE（Mixture of Experts）混合专家架构**，核心原理：

- **高噪声专家**：负责视频生成早期的高噪声去噪阶段，建立全局结构和语义框架
- **低噪声专家**：负责后期低噪声精细去噪阶段，补充细节、增强画质和运动流畅性
- **动态路由**：根据去噪时间步自动分配至对应专家模型，无需用户手动切换

> 每次视频生成需要同时加载高噪声和低噪声两个专家模型，这也是 14B 版本显存需求较高的根本原因。

#### 1.4.1 模型架构详解

Wan 2.2 14B 的完整模型架构由以下核心组件构成：

| 组件        | 文件                                            | 参数量  | 功能                              | 精度                          |
| --------- | --------------------------------------------- | ---- | ------------------------------- | --------------------------- |
| **文本编码器** | `umt5_xxl_fp8_e4m3fn_scaled.safetensors`      | ~10B | 将文本提示词编码为语义嵌入向量                 | fp8                         |
| **高噪声专家** | `wan2.2_t2v/i2v_high_noise_14B_*.safetensors` | ~14B | 处理高时间步去噪（t=1000~500），建立全局结构     | T2V: fp8_scaled / I2V: fp16 |
| **低噪声专家** | `wan2.2_t2v/i2v_low_noise_14B_*.safetensors`  | ~14B | 处理低时间步去噪（t=500~0），精细化细节和运动      | T2V: fp8_scaled / I2V: fp16 |
| **VAE**   | `wan_2.1_vae.safetensors`                     | —    | 编码图片为 latent / 解码 latent 为视频帧像素 | fp16                        |
| **动态路由器** | 集成在 ComfyUI 工作流中                              | —    | 根据时间步选择调用高噪声或低噪声专家              | —                           |

#### 1.4.2 三种生成模式的输入输出流程

**流程一：文生视频（14B T2V）**

```
步骤1 — 输入
  用户输入正向提示词（必填） + 反向提示词（可选）
  例: "A beautiful sunset over a calm ocean, cinematic lighting"

步骤2 — 文本编码
  正向提示词 → UMT5-XXL → 条件嵌入向量 c_pos
  反向提示词 → UMT5-XXL → 无条件嵌入向量 c_neg
  （若未填反向提示词，使用空字符串生成 c_neg）

步骤3 — 潜空间初始化
  根据种子值(seed)生成随机噪声 latent_x₀
  形状: [C, H, W, T]，如 480p/81帧: [16, 30, 48, 81]
  C=latent通道数, H/W=空间维度, T=时间帧数

步骤4 — MoE 去噪迭代（30步）
  for step i in [0, 29]:
    计算当前时间步 t_i（从1000递减至0）
    if t_i > 500:
      使用高噪声专家模型预测噪声
    else:
      使用低噪声专家模型预测噪声
    
    CFG 引导计算:
      noise_cond   = Expert(latent_x, t_i, c_pos)     ← 条件预测
      noise_uncond = Expert(latent_x, t_i, c_neg)     ← 无条件预测
      noise_pred   = noise_uncond + cfg_scale × (noise_cond - noise_uncond)
    
    更新 latent:
      latent_x = latent_x - noise_pred × step_weight
    
  最终得到去噪完成的 latent_x_clean

步骤5 — VAE 解码输出
  latent_x_clean → VAE Decoder → 视频帧像素序列
  像素序列 → 合成 MP4 文件（指定 FPS, 默认16fps）
  
  输出: 480p × 81帧 × 16fps = ~5秒 MP4 视频
```

**流程二：图生视频（14B I2V）**

```
步骤1 — 输入
  用户上传图片（PNG/JPG/WebP）+ 运动描述提示词
  例: 图片=风景照片, 提示词="The wind blows through the trees gently"

步骤2 — 双路编码
  提示词 → UMT5-XXL → 条件/无条件嵌入向量（同T2V）
  图片 → VAE Encoder → 图片 latent（形状: [C, H, W, 1]）

步骤3 — 潜空间初始化
  图片 latent 拼接到随机噪声 latent 上
  latent_x₀ = concat([图片latent, 随机噪声latent], axis=T)
  首帧保留图片信息，后续帧由模型生成运动内容

步骤4 — MoE 去噪迭代（30步）
  同 T2V 流程，但条件嵌入中包含图片信息引导
  高噪声专家: 确保视频首帧与输入图片一致，建立运动方向
  低噪声专家: 精细渲染运动细节，保持图片内容一致性

步骤5 — VAE 解码输出
  同 T2V，输出 MP4 视频
  首帧与输入图片高度一致，后续帧展现运动效果
```

**流程三：首尾帧生成（14B FLF2V）**

```
步骤1 — 输入
  用户上传起始帧图片 + 结束帧图片 + 过渡描述提示词（可选）
  例: 首帧=白天城市, 尾帧=夜晚城市, 提示词="Day transitions to night smoothly"

步骤2 — 三路编码
  提示词 → UMT5-XXL → 条件/无条件嵌入向量
  起始帧 → VAE Encoder → 首帧 latent [C, H, W, 1]
  结束帧 → VAE Encoder → 尾帧 latent [C, H, W, 1]

步骤3 — 潜空间初始化
  首帧 latent + 随机噪声 latent + 尾帧 latent 拼接
  latent_x₀ = concat([首帧latent, 随机噪声latent, 尾帧latent], axis=T)
  首帧锁定开头画面，尾帧锁定结尾画面，中间帧为过渡区域

步骤4 — MoE 去噪迭代（30步）
  同 I2V 流程，但条件嵌入同时包含首尾帧信息
  高噪声专家: 建立首→尾的整体过渡结构
  低噪声专家: 精细渲染中间过渡帧的运动和变化细节
  生成结果确保: 首帧≈起始帧, 尾帧≈结束帧, 中间帧平滑过渡

步骤5 — VAE 解码输出
  同 T2V/I2V，输出 MP4 视频
  首帧与起始帧高度一致，尾帧与结束帧高度一致
```

#### 1.4.3 关键技术参数说明

| 参数             | 说明                          | 对生成的影响                          |
| -------------- | --------------------------- | ------------------------------- |
| **时间步范围**      | t=1000（纯噪声）→ t=0（清晰视频）      | 定义去噪过程的起点和终点                    |
| **高/低噪声专家切换点** | t≈500（约第15步，默认30步时）         | 切换点决定两个专家各自的去噪范围                |
| **CFG Scale**  | 条件引导强度，默认5                  | 值越高→更遵循提示词但可能过饱和；值越低→更自由但可能偏离语义 |
| **采样步数**       | 默认30步                       | 步数越多→品质越好但越慢；步数太少→结构不完整         |
| **种子值(seed)**  | 控制初始随机噪声                    | 相同seed+相同参数=可复现结果               |
| **分辨率/帧数**     | 480p/81帧为默认                 | 更高分辨率或更多帧数需要更多VRAM和更长时间         |
| **FP精度**       | T2V: fp8_scaled / I2V: fp16 | fp8省显存但精度略低；fp16精度更高但显存占用更多     |

> **架构图**：上方已展示 Wan 2.2 14B MoE 从输入到输出视频的完整架构流程图，包含输入层、编码层、潜空间初始化、MoE 双专家去噪核心、迭代循环、VAE 解码和输出层。

### 2.2 核心使用场景

#### 场景 1：短视频内容创作

> 创作者输入一句话或上传一张草图，平台自动生成 5-10 秒电影级短视频，用于抖音/小红书/B站等平台发布。

- 频次：每日 10-50 条
- 品质要求：高（14B MoE 架构保障品质）
- 时长要求：5-15 秒

#### 场景 2：广告素材批量生成

> 广告团队基于品牌视觉资产（图片/品牌色/风格），批量生成不同版本的广告视频素材，快速 AB 测试。

- 频次：项目制，单项目 50-200 条
- 品质要求：极高（14B 电影级美学）
- 时长要求：5-30 秒

#### 场景 3：电商商品视频化

> 电商运营上传商品静态主图，一键生成商品展示动态视频，提升转化率。

- 频次：每日 100-1000 条
- 品质要求：高（14B I2V 保持图片一致性）
- 时长要求：3-5 秒

#### 场景 4：影视概念可视化

> 导演/编剧输入剧本片段描述，快速生成概念视频预览；或提供首尾帧，生成过渡动画，辅助决策。

- 频次：低频，项目制
- 品质要求：极高（14B T2V + FLF2V）
- 时长要求：5-15 秒

#### 场景 5：教育培训动画

> 教师输入知识点描述，生成教学演示动画视频。

- 频次：中频
- 品质要求：高（14B 精准语义遵循）
- 时长要求：5-15 秒

## 4. 功能详细描述

### 4.1 视频生成核心

#### 4.1.1 文生视频（14B T2V）

| 属性       | 说明                                         |
| -------- | ------------------------------------------ |
| **功能描述** | 用户输入文本提示词，系统生成对应电影级品质视频                    |
| **模型架构** | Wan 2.2 14B MoE（高噪声专家 + 低噪声专家协同去噪）         |
| **输入**   | 正向提示词（必填）、反向提示词（可选）                        |
| **输出**   | MP4 格式视频文件                                 |
| **参数**   | 分辨率、帧数、采样步数、种子值、CFG Scale                  |
| **默认参数** | 480p / 81帧(约5秒@16fps) / 30步 / 随机种子 / CFG=5 |

**模型文件配置：**

| 节点                          | 加载文件                                               |
| --------------------------- | -------------------------------------------------- |
| `Load Diffusion Model`（节点1） | `wan2.2_t2v_high_noise_14B_fp8_scaled.safetensors` |
| `Load Diffusion Model`（节点2） | `wan2.2_t2v_low_noise_14B_fp8_scaled.safetensors`  |
| `Load CLIP`                 | `umt5_xxl_fp8_e4m3fn_scaled.safetensors`           |
| `Load VAE`                  | `wan_2.1_vae.safetensors`                          |

> ⚠️ **重要**：14B T2V 需同时加载**两个** diffusion 模型文件（高噪声 + 低噪声），缺一不可。

**提示词输入规范：**

- 支持中文和英文提示词
- 最大长度：512 字符
- 支持提示词模板变量（如 `{{风格}}`、`{{场景}}`）
- 提供提示词优化建议（自动补全、语法检查）

**反向提示词预设选项：**

- 基础质量：`low quality, blurry, distorted, artifacts`
- 运动问题：`static, jittery, inconsistent motion`
- 内容排除：`watermark, text overlay, logo`

#### 4.1.2 图生视频（14B I2V）

| 属性       | 说明                                 |
| -------- | ---------------------------------- |
| **功能描述** | 用户上传一张图片 + 运动描述提示词，生成基于图片内容的动态视频   |
| **模型架构** | Wan 2.2 14B MoE（高噪声专家 + 低噪声专家协同去噪） |
| **输入**   | 图片（必填，PNG/JPG/WebP）、运动描述提示词（必填）    |
| **输出**   | MP4 格式视频文件                         |
| **图片限制** | 最大分辨率 2048×2048、最大文件大小 10MB        |

**模型文件配置：**

| 节点                          | 加载文件                                         |
| --------------------------- | -------------------------------------------- |
| `Load Diffusion Model`（节点1） | `wan2.2_i2v_high_noise_14B_fp16.safetensors` |
| `Load Diffusion Model`（节点2） | `wan2.2_i2v_low_noise_14B_fp16.safetensors`  |
| `Load CLIP`                 | `umt5_xxl_fp8_e4m3fn_scaled.safetensors`     |
| `Load VAE`                  | `wan_2.1_vae.safetensors`                    |

**图片预处理：**

- 自动裁剪/缩放至模型支持的分辨率
- 提供手动裁剪工具
- 支持图片增强（去噪、超分辨率）

#### 4.1.3 首尾帧生成（14B FLF2V）

| 属性       | 说明                              |
| -------- | ------------------------------- |
| **功能描述** | 用户上传起始帧和结束帧图片，系统生成从起始到结束的过渡视频   |
| **模型架构** | 复用 14B I2V 模型（无需额外下载模型）         |
| **输入**   | 起始帧图片（必填）、结束帧图片（必填）、过渡描述提示词（可选） |
| **输出**   | MP4 格式视频文件                      |
| **特殊参数** | 过渡帧数、运动幅度控制                     |

**特色优势：**

- 独有的首尾帧过渡能力，竞品无此功能
- 可精确控制视频开头和结尾的视觉状态
- 适用于动画过渡、场景切换、物体变形等高级创作场景

#### 4.1.4 视频风格迁移（V2V）— P3 远期

| 属性       | 说明                     |
| -------- | ---------------------- |
| **功能描述** | 输入一段视频 + 风格提示词，生成风格化视频 |
| **模型架构** | 待 Wan 2.2 后续版本或自定义节点支持 |
| **输入**   | 源视频 + 风格提示词            |
| **输出**   | MP4 格式风格化视频            |

### 4.2 创作控制

#### 4.2.1 参数调节面板

| 参数             | 范围                     | 默认值        | 说明                                     |
| -------------- | ---------------------- | ---------- | -------------------------------------- |
| **分辨率**        | 480p / 720p / 1080p    | 480p       | 720p 推荐 ≥24GB VRAM；1080p 推荐 ≥48GB VRAM |
| **帧数（length）** | 33-161                 | 81         | 约 2-10 秒@16fps                         |
| **采样步数**       | 10-50                  | 30         | 步数越多品质越好但越慢                            |
| **种子值**        | -1（随机）或具体整数            | -1         | 固定种子可复现结果                              |
| **CFG Scale**  | 1-20                   | 5          | 提示词引导强度                                |
| **FPS**        | 8/12/16/24             | 16         | 输出视频帧率                                 |
| **专家模型选择**     | high_noise + low_noise | 自动（MoE双专家） | 14B 必须同时加载两个专家模型                       |

#### 4.4.1 模型管理与切换

| 功能                | 说明                                 |

| 场景    | 推荐模型        | 原因                  |

| **任务取消** | 用户可取消排队中或生成中的任务               |
| **任务重试** | 失败任务支持一键重试                    |

| **服务层**        | Python (FastAPI / Flask)   | API 路由、任务调度、用户管理       |
| **ComfyUI 引擎** | ComfyUI（Python）            | 工作流执行、MoE 双专家模型加载、视频生成 |
| **数据库**        | PostgreSQL / SQLite        | 用户数据、任务记录、资产索引         |
| **文件存储**       | 本地磁盘 / OSS                 | 视频文件、图片、模型文件           |
| **消息队列**       | Redis / 内置队列               | 任务排队、状态推送              |
| **模型推理**       | PyTorch + CUDA             | Wan 2.2 14B 模型 GPU 推理  |

### 5.3 ComfyUI 集成方式

| 集成方式       | 说明                                     | 适用场景              |
| ---------- | -------------------------------------- | ----------------- |
| **API 模式** | ComfyUI 启动后暴露 HTTP API，服务层通过 API 提交工作流 | ✅ 推荐，最灵活          |
| **嵌入式**    | 服务层直接 import ComfyUI 模块                | 定制化强但耦合度高         |
| **自定义节点**  | 开发 ComfyUI 自定义节点扩展功能                   | 需要扩展 ComfyUI 内部能力 |

**推荐方案：API 模式**

ComfyUI 启动后提供完整的 REST API，服务层通过以下流程实现视频生成：

```
1. 服务层将用户请求转换为 ComfyUI 工作流 JSON
2. 在工作流 JSON 中配置两个 Load Diffusion Model 节点（高噪声 + 低噪声）
3. 通过 POST /prompt 提交到 ComfyUI API
4. ComfyUI 执行工作流并返回 prompt_id
5. 通过 WebSocket 或轮询获取执行状态
6. 生成完成后从 ComfyUI 输出目录获取视频文件
```

### 5.4 工作流模板映射

| 产品功能      | ComfyUI 工作流              | Diffusion 模型文件                                               | VAE 文件      |
| --------- | ------------------------ | ------------------------------------------------------------ | ----------- |

| 图生视频（14B） | wan22_i2v_14B workflow   | i2v_high_noise_14B_fp16 + i2v_low_noise_14B_fp16             | wan_2.1_vae |
| 首尾帧生成     | wan22_flf2v_14B workflow | 复用 i2v 模型文件                                                  | wan_2.1_vae |

> **所有 14B 模型共用**：`umt5_xxl_fp8_e4m3fn_scaled.safetensors`（文本编码器）和 `wan_2.1_vae.safetensors`（VAE）

### 6.1 最低硬件要求

| 配置项          | 最低要求                        | 推荐配置            | 说明                 |

### 6.2 生成性能指标

| 模型        | 分辨率  | 帧数 | 步数          | 预估时间（A100 80GB） | 预估时间（RTX 4090 24GB） |
| --------- | ---- | -- | ----------- | --------------- | ------------------- |
| 14B T2V   | 480p | 81 | 30          | ~5-8 分钟         | ~5-8 分钟             |
| 14B I2V   | 480p | 81 | 30          | ~5-8 分钟         | ~5-8 分钟             |

| 14B T2V   | 720p | 81 | 30          | ~10-15 分钟       | ~10-15 分钟           |
| 14B T2V   | 480p | 81 | 30（GGUF Q8） | ~3-5 分钟         | ~3-5 分钟             |

> **注意**：实际生成时间受 GPU 型号、显存大小、系统负载等因素影响，需实际测试后校准。16GB VRAM 需开启 offloading，生成时间会额外增加 2-5 分钟。

## 11. 风险与应对

| 风险                 | 等级 | 影响                  | 应对策略                                              |
| ------------------ | -- | ------------------- | ------------------------------------------------- |
| **14B 显存需求高**      | 高  | 16GB 以下 GPU 无法运行    | GGUF 量化版 / ComfyUI offloading + 充足系统内存 / 明确最低硬件要求 |
| **双专家模型加载慢**       | 高  | 首次生成等待时间长           | 模型预热机制 / 模型常驻显存（避免反复加载） / fp8_scaled 精度减少加载量      |
| **生成速度慢**          | 高  | 14B 生成时间较长，用户体验差    | 预热模型 / 优化步数 / 提供 4步 LoRA 加速选项 / 进度条缓解等待焦虑         |
| **内容安全风险**         | 高  | 生成违规内容，合规问题         | 提示词过滤 + 生成内容审核 + 水印标识                             |
| **并发瓶颈**           | 中  | 14B 双专家模型占用显存大，并发受限 | 任务队列 + 多 GPU 扩展 + 云端弹性                            |
| **模型版本升级**         | 中  | Wan 2.3/2.4 发布后需适配  | 关注官方更新，预留模型版本管理机制                                 |
| **存储增长**           | 低  | 磁盘空间不足              | 自动清理策略 + 冷热分层存储                                   |
| **ComfyUI API 变更** | 低  | 集成层需适配              | 版本锁定 + 变更监控                                       |
